# GitLab Pajamas

## Visual thesis

Large development workflows remain scannable through clear grouping and page structure. Color and spacing roles stay predictable across many features and teams.

## Signature relationships

1. **dense task hierarchy.** Large development workflows remain scannable through clear grouping and page structure.
2. **semantic token discipline.** Color and spacing roles stay predictable across many features and teams.
3. **inclusive interaction.** Content, focus, keyboard behavior, and alternative input are treated as product requirements.
4. **incremental consistency.** Reusable patterns support change without requiring every screen to be rebuilt at once.

## Dense task hierarchy in practice

Application shell with layered content regions. Large development workflows remain scannable through clear grouping and page structure.

Color and spacing roles stay predictable across many features and teams.

Content, focus, keyboard behavior, and alternative input are treated as product requirements. Reusable patterns support change without requiring every screen to be rebuilt at once.

Minimal feedback for state and navigation.

## Adaptation rules

- Suitable contexts: complex developer and operations platforms, and large product families with many contributors and recurring workflow patterns.
- Preserve: dense task hierarchy and semantic token discipline.
- Poor fit: small expressive campaigns where dense application conventions would overpower the story.

## Failure modes

- Compressing dense screens without preserving headings and landmarks.
- Using status colors without text or shape reinforcement.
- Adding one-off component variants that bypass the shared semantics.
