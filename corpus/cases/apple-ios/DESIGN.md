# Apple iOS Guidance

## Visual thesis

Primary actions remain reachable, legible, and physically credible on a handheld screen. Bars, sheets, tabs, and transitions preserve location without imitating a desktop window model.

## Signature relationships

1. **touch-first hierarchy.** Primary actions remain reachable, legible, and physically credible on a handheld screen.
2. **platform-shaped navigation.** Bars, sheets, tabs, and transitions preserve location without imitating a desktop window model.
3. **content-led chrome.** System controls support the current task while content keeps visual priority.
4. **adaptive input.** Touch, keyboard, pointer, orientation, text size, and assistive technology can change without breaking the task.

## Touch-first hierarchy in practice

Single mobile reading spine with bounded sheets and bars. Primary actions remain reachable, legible, and physically credible on a handheld screen.

Bars, sheets, tabs, and transitions preserve location without imitating a desktop window model.

System controls support the current task while content keeps visual priority. Touch, keyboard, pointer, orientation, text size, and assistive technology can change without breaking the task.

Short continuity cues with full reduced-motion parity.

## Adaptation rules

1. Suitable contexts: touch-first iPhone applications with platform-native interaction, and mobile products that need familiar navigation and adaptive input.
2. Preserve: touch-first hierarchy and platform-shaped navigation.
3. Poor fit: desktop-first workspaces whose core task requires persistent wide-screen comparison.

## Failure modes

1. Shrinking a desktop composition until it technically fits a phone.
2. Hiding the user's location behind ornamental transitions.
3. Treating large text or alternate input as an edge case.
