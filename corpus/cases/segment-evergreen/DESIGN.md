## Pragmatic composition in practice

Compact application grid with focused configuration container. Reusable primitives favor clear product assembly over visual novelty.

Forms, dialogs, tables, and feedback support technical setup tasks.

Components expose options while retaining predictable defaults. Neutral surfaces let names, states, and actions carry emphasis.

Direct dialog and validation feedback.

## Adaptation rules

1. Suitable contexts: developer-facing SaaS with setup and administration workflows, and teams needing a compact composable component foundation.
2. Preserve: pragmatic composition and configuration clarity.
3. Poor fit: brand campaigns that depend on expressive media and irregular layout.

## Failure modes

1. Adding variants faster than the system can explain them.
2. Hiding setup consequences in generic dialog copy.
3. Using quiet hierarchy as an excuse for pale text.
