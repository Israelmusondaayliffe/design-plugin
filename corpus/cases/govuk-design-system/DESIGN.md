# GOV.UK Design System

## Visual thesis

This system is designed to make public services understandable, predictable, and usable under pressure. Its taste is not minimalism for its own sake. It is disciplined refusal to make a citizen relearn controls, color meaning, or page structure while trying to complete an important task.

## Signature relationships

- **Convention is a feature.** Core controls remain visually and behaviorally stable across services.
- **Content drives layout.** Headings, explanatory copy, form questions, errors, and next actions create the page rhythm.
- **Color carries meaning.** Existing roles should not be reassigned for decoration.
- **Patterns extend components.** A date input alone is not a service. The surrounding task, sequence, recovery, and confirmation matter.
- **Accessibility is visible.** Focus, errors, labels, and readable contrast should be obvious rather than aesthetically hidden.

## Layout and density

Favor a clear reading column, strong headings, obvious page progression, and enough space around questions to prevent accidental grouping. Dense dashboards are not the model. Multi-step service pages should make the current task unmistakable.

## Typography

Typography should be plain, high contrast, and structurally meaningful. Large headings establish task context. Body copy explains only what the user needs. Labels and error text should remain visible and literal.

## Color and surfaces

Use color sparingly and semantically. The page does not need multiple decorative surfaces to create hierarchy. White space, type, rules, and control states do most of the work.

## Components and interaction

Forms, radios, checkboxes, date input, summary lists, error summaries, buttons, and navigation should use a repeatable service grammar. Error recovery and keyboard focus must be designed, not implied.

## Adaptation rules

- Preserve predictable controls, task-first content hierarchy, semantic color, error clarity, and pattern-level thinking.
- Brand adaptation can change typeface, palette, and header treatment only if familiarity and accessibility remain strong.
- For commercial products, borrow the service rigor without copying government branding.

## Failure modes

- Styling the page like GOV.UK while inventing unfamiliar interaction behavior.
- Adding card grids, gradients, and decorative badges that make the service hierarchy less clear.
- Using color alone to communicate validation or status.
- Optimizing for visual novelty over completion confidence.

## Evidence boundary

This is original analysis of public GOV.UK Design System guidance. No government logos, screenshots, or copied component markup are stored in this case.
