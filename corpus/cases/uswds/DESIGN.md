# U.S. Web Design System

## Visual thesis

USWDS is strongest as a public-service continuity system. It combines reusable components and tokens with journey patterns and explicit design principles so people can complete important tasks across agencies, devices, and levels of technical confidence.

## Signature relationships

- **User need before agency expression.** The current public task should dominate the page.
- **Accessibility is foundational.** Components and patterns must work for diverse people and devices.
- **Mobile friendliness is service quality.** Responsive behavior cannot be treated as a desktop layout compressed later.
- **Patterns extend components into journeys.** A component library alone is not enough for benefits, applications, identity, or account flows.
- **Continuity builds trust.** Common actions and page structures should remain familiar across related services.

## Layout and density

Use clear reading order, strong headings, literal actions, and enough spacing to distinguish questions and sections. On mobile, preserve task context and next action while reducing secondary complexity thoughtfully.

## Typography

Typography should prioritize readability, scanning, and plain-language hierarchy. Use headings to tell people where they are in the service and labels to state exactly what is required.

## Color and surfaces

Use color semantically for links, actions, status, validation, and emphasis. Do not turn patriotic or agency colors into a decorative substitute for hierarchy.

## Components and interaction

Forms, alerts, navigation, accordions, summaries, identifiers, and service patterns should expose visible focus, validation, and recovery. Multi-step work should make progress and consequences understandable.

## Adaptation rules

- Preserve accessibility, user-need hierarchy, mobile service quality, and journey continuity.
- Adapt identity through typography, illustration, and restrained brand roles without changing familiar control meaning.
- Use pattern research for complex journeys rather than designing each step independently.

## Failure modes

- Treating public-sector design as a patriotic palette.
- Compressing desktop service pages into unreadable mobile stacks.
- Using reusable components without solving the journey between them.
- Hiding validation, progress, or next actions in subtle styling.

## Evidence boundary

This case is original analysis of public USWDS guidance. It contains no agency logos, screenshots, or copied government assets.
