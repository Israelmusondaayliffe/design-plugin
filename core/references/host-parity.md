# Host parity contract

The OpenAI and Claude Code packages are generated from one shared core. Every shared file must be byte-identical. Host overlays may differ only where the host requires a different manifest, invocation syntax, or capability handoff.

## Equivalent shared behavior

Both hosts provide the same three user workflows:

- Run for a new end-to-end design project
- Audit for an existing interface
- Resume for durable project state

Both hosts use the same interview, approval, research, direction, system-definition, token, build-wave, render-evidence, QA, repair, audit, and proposal-only learning contracts. The same artifact schemas, state gates, pass ceilings, privacy-marker checks, and package boundaries apply.

## Accepted host differences

| Concern | OpenAI and Codex | Claude Code |
|---|---|---|
| Explicit invocation | `$design:run`, `$design:audit`, `$design:resume` | `/design:run`, `/design:audit`, `/design:resume` |
| Manifest | `.codex-plugin/plugin.json` with Codex interface metadata | `.claude-plugin/plugin.json` with Claude Code metadata |
| Built-in capabilities | Detect OpenAI-host browser, image, Figma, and coding capabilities | Detect Claude-host browser, image, Figma, and coding capabilities |
| Missing capability | Record a blocker or produce the approved fallback artifact | Record a blocker or produce the approved fallback artifact |
| Installation | Codex local marketplace | Claude Code local marketplace |

Manifest validation and shared-file parity do not prove that both hosts route or execute identically. Each claimed host behavior needs its own runtime evidence. Isolated host qualification uses temporary host configurations and records any remaining runtime limit.

## Package boundary

Neither package includes an MCP server, Refero runtime dependency, full corpus, reference Site, browser binary, screenshot, render, font, generated bytecode, or host account data.
