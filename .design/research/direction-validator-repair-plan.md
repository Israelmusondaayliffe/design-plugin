# Direction validator repair proposal

Status: Awaiting user authorization. No plugin runtime or product file has been changed.

## Problem

The approved Benchmark 2 brief requires three meaningfully different adaptations of IBM Carbon while keeping Carbon as the single dominant foundation. The current direction validator rejects any substantial direction set that repeats a primary reference slug, even when all nine dimension signatures differ.

This is a blocking workflow defect. Faking three Carbon aliases or introducing two co-equal foundations would violate the approved brief.

## Required behavior

Keep the existing distinct-primary rule as the default. Add one explicit direction-set strategy for approved projects that require several adaptations of a single foundation:

- `distinct-primary-foundations`: current behavior and default when the field is absent.
- `single-foundation-adaptations`: allowed only for substantial direction sets.

An absent `direction_strategy` uses the default. Any explicit value outside those two strings, including `null` or an empty string, must fail validation.

For `single-foundation-adaptations`, validation must require:

- three to five directions;
- exactly one shared primary reference slug;
- one unique, non-empty string `adaptation_axis` per direction, compared after trimming and case folding;
- at least four different dimension signatures for every direction pair;
- the existing primary-responsibility, secondary-role, evidence, role-invariant, forbidden-drift, risk, and feasibility rules.

The exception changes only how distinctness is proved. It does not permit cosmetic variants, broad supporting references, or source-identity copying.

## Required tests

- Existing substantial direction sets still reject repeated primary slugs by default.
- A `single-foundation-adaptations` set passes only when all directions share one primary, carry unique adaptation axes, and meet the four-of-nine difference floor.
- The default applies only when `direction_strategy` is absent; unknown, `null`, and empty strategy values fail.
- The new strategy rejects mixed primaries, missing axes, non-string or whitespace-only axes, axes duplicated after trimming and case folding, fewer than three directions, bounded-repair use, and direction pairs below the four-dimension floor.
- A schema contract test checks the two-value strategy enum and the conditional `adaptation_axis` requirement. Runtime validation remains authoritative for normalized axis uniqueness.
- The existing Wave 5 CLI test passes its temporary project root explicitly, keeping synthetic fixtures isolated from this repository's live Design state.
- The complete existing test suite passes.
- OpenAI and Claude distributions rebuild deterministically at `0.1.0-dev.11`, retain shared-core parity, and pass isolated update checks from `0.1.0-dev.10`.
