## Decision

The Site will treat each public design case as an evidence-bounded, well-explained data package. Before downloading, a user can understand the case context, intent, value, evidence quality, provenance, limitations, available formats, and recovery paths.

Readable and structured outputs must carry matching reviewed meaning. Human explanation leads, while provenance, file metadata, evidence IDs, and machine-readable identifiers remain precise and compact.

## Source responsibilities

- IBM Carbon owns the grid, semantic layers, component-state logic, contextual surfaces, and productive versus expressive hierarchy.
- Vercel Geist contributes typography detail for explanation, labels, provenance, values, file details, and identifiers only.
- GOV.UK contributes exact error and recovery behavior only.
- GitHub Primer contributes complete mobile reflow only.

No supporting reference may become a co-equal visual foundation.

## Required design logic

- Present context, intent, value, evidence quality, provenance, limitations, format, and file action in that decision order.
- Keep explanation readable and technical records compact.
- Use original semantic roles for ready, incomplete, unavailable, stale, warning, error, focus, and download states.
- Show only original previews derived from approved public case data.
- Let users inspect contents, choose readable or structured output, download, and recover from a specific failure without losing context.
- Keep the complete task available after mobile reflow.

## Forbidden drift

- Do not present a download before its context, contents, evidence boundary, and limitations are visible.
- Do not make metadata visually equal to the human-readable explanation.
- Do not use fabricated previews, copied source assets, or decorative code blocks as proof.
- Do not write generic failure messages without the exact problem and next action.
- Do not copy Carbon geometry, IBM blue, Geist monochrome identity, GOV.UK styling, or GitHub's product shell.

## Accepted tradeoff

This direction makes the download itself the main product. It can feel like a file registry if technical detail overwhelms discovery and visual case character. The next system-definition phase must protect discovery while preserving the evidence and file contract.

## Authority boundary

This selection does not authorize system definition, repository changes, Site implementation, installation, deployment, publication, or external writes. Those actions remain behind their existing Design gates.
